
# Hono + Prisma + Connection Pooling (Serverless Backend Notes)

---

## 1️⃣ What We Are Building

* **Backend application**
* **Hono framework** (lightweight, fast)
* **Prisma ORM** (database access)
* **Serverless environment** (Cloudflare Workers)
* **Prisma Connection Pooling (Prisma Accelerate)**

---

## 2️⃣ What is Hono?

* Hono is a **web framework** for:

  * Cloudflare Workers
  * Edge environments
  * Serverless platforms
* Similar to Express but:

  * Faster
  * Smaller
  * Designed for serverless

---

## 3️⃣ What is Prisma?

* Prisma is an **ORM (Object Relational Mapper)**
* Allows us to:

  * Define database schema
  * Run migrations
  * Query DB using JavaScript / TypeScript
* Works with:

  * PostgreSQL
  * MySQL
  * SQLite
  * MongoDB

---

## 4️⃣ What is Serverless Backend?

Serverless backend means:

* No long-running server
* No permanent process
* A new instance may be created **per request**

### Examples:

* Cloudflare Workers
* AWS Lambda
* Vercel Edge Functions

---

## 5️⃣ Problem in Serverless Databases

Each request:

* Creates a new runtime
* Opens a new DB connection

Result:
❌ Too many database connections
❌ Database crashes

---

## 6️⃣ What is Prisma Connection Pooling?

Connection pooling:

* Reuses a **small set of DB connections**
* Prevents creating new connections per request
* Required for **serverless / edge environments**

Prisma provides this using:
➡ **Prisma Accelerate**

---

## 7️⃣ Connection Pooling Example

### ❌ Without pooling

```
100 requests
→ 100 DB connections
→ DB limit exceeded
→ Crash
```

### ✅ With pooling

```
100 requests
→ 5–10 shared connections
→ Stable backend
```

## 8️⃣ Project Setup Steps

### Step 1: Create Hono App

```bash
npm create hono@latest
```

Choose:

* Cloudflare Workers
* TypeScript

---

### Step 2: Install Prisma

```bash
npm install prisma
```

Initialize Prisma:

```bash
npx prisma init
```

This creates:

* `prisma/schema.prisma`
* `.env`

---

## 9️⃣ Database URLs (IMPORTANT)

### 1️⃣ Normal Database URL (`.env`)

Used for:

* Local development
* Prisma migrations

```env
DATABASE_URL="postgresql://username:password@host:5432/dbname"
```

---

### 2️⃣ Prisma Accelerate (Pooled URL)

Used for:

* Production
* Cloudflare Workers

Get from:
👉 Prisma Accelerate Dashboard

Format:

```text
prisma://accelerate.prisma-data.net/?api_key=YOUR_API_KEY
```

Add this to **`wrangler.jsonc`**:

```jsonc
{
  "vars": {
    "DATABASE_URL": "prisma://accelerate.prisma-data.net/?api_key=YOUR_API_KEY"
  }
}
```

---

## 🔥 Why Two URLs Are Needed

| Purpose            | URL Location     |
| ------------------ | ---------------- |
| Migrations         | `.env`           |
| Serverless runtime | `wrangler.jsonc` |

⚠ **Never run migrations using pooled URL**

---

## 🔟 Run Prisma Migration

```bash
npx prisma migrate dev --name init
```

* Creates database tables
* Applies schema changes
* Uses normal DB connection

---

## 1️⃣1️⃣ Final Architecture Diagram

```
Client / Browser
      ↓
Cloudflare Worker (Hono)
      ↓
Prisma Client
      ↓
Prisma Accelerate (Connection Pool)
      ↓
PostgreSQL (Neon / Supabase / RDS)
```

---

## 1️⃣2️⃣ Key Points to Remember

* Hono → serverless backend framework
* Prisma → ORM
* Serverless → needs connection pooling
* Prisma Accelerate → provides pooling
* `.env` → migrations only
* `wrangler.jsonc` → production runtime

---

## 🧠 One-Line Summary

> Prisma connection pooling allows serverless backends to safely access databases without exhausting DB connections.
